Todo dispositivo LaundryCtrl é inicialmente instalado com o firmware de
fábrica. Nesse estado, o dispositivo opera em modo \textbf{Access Point (AP)}
e disponibiliza um servidor \http{} embarcado exclusivamente para
configuração da rede Wi-Fi.

Após a configuração e confirmação das redes Wi-Fi, o dispositivo reinicia e
conecta-se à rede com melhor sinal.

A partir do momento em que a conexão Wi-Fi é estabelecida, \textbf{todas as
operações de configuração, provisionamento e instalação são realizadas
exclusivamente através de \mqtt{}}.

O \http{} não é utilizado para nenhuma configuração operacional após a
conexão do dispositivo à rede.

O processo é dividido nas seguintes etapas:

\begin{enumerate}
    \item Configuração das redes Wi-Fi via \http{}.
    \item Confirmação da configuração Wi-Fi.
    \item Reinicialização e conexão à rede.
    \item Conexão ao broker \mqtt{}.
    \item Configuração do dispositivo via \mqtt{}.
    \item Provisionamento dos certificados via \mqtt{}.
    \item Execução do processo de instalação via \mqtt{}.
    \item Inicialização do firmware de produção.
\end{enumerate}


Cada dispositivo possui um identificador baseado em seu endereço MAC.

O SSID criado pelo dispositivo durante o modo AP possui o formato:

\begin{lstlisting}[style=code]
laundryctrl-AABBCCDDEEFF
\end{lstlisting}

onde \texttt{AABBCCDDEEFF} representa o endereço MAC do dispositivo.

Dessa forma, cada dispositivo possui um SSID único.

O servidor \http{} do modo AP utiliza o endereço:

\begin{lstlisting}[style=code]
192.168.4.1
\end{lstlisting}


\subsection{Modo AP}

Ao iniciar com o firmware de fábrica, o dispositivo cria uma rede Wi-Fi
própria.

O instalador deve:

\begin{enumerate}
    \item localizar o SSID \texttt{laundryctrl-id};
    \item conectar-se à rede;
    \item acessar \texttt{192.168.4.1};
    \item configurar uma ou mais redes Wi-Fi;
    \item confirmar a configuração.
\end{enumerate}

\textbf{Somente a configuração do Wi-Fi é realizada através de \http{}.}

\subsection{Configuração das redes}

O dispositivo armazena até quatro redes Wi-Fi.

Ele poderá utilizar essas redes para selecionar automaticamente aquela que
apresentar o melhor sinal.

Apenas uma rede é obrigatória.

\subsubsection{Endpoint}

\begin{lstlisting}[style=code]
POST /conf/wifi/networks
\end{lstlisting}

\subsubsection{Rede 1}

\begin{lstlisting}[style=json]
{
    "net": 1,
    "ssid": "ssid",
    "pswd": "senha"
}
\end{lstlisting}

\subsubsection{Rede 2}

\begin{lstlisting}[style=json]
{
    "net": 2,
    "ssid": "ssid",
    "pswd": "senha"
}
\end{lstlisting}

\subsubsection{Rede 3}

\begin{lstlisting}[style=json]
{
    "net": 3,
    "ssid": "ssid",
    "pswd": "senha"
}
\end{lstlisting}

\subsubsection{Rede 4}

\begin{lstlisting}[style=json]
{
    "net": 4,
    "ssid": "ssid",
    "pswd": "senha"
}
\end{lstlisting}

\subsubsection{Resposta}

\begin{lstlisting}[style=json]
{
    "result": 1
}
\end{lstlisting}

onde:

\begin{itemize}
    \item \texttt{0}: falha ao salvar a configuração;
    \item \texttt{1}: configuração salva com sucesso.
\end{itemize}


Após configurar as redes desejadas, o instalador deve informar
explicitamente ao dispositivo que a configuração está concluída.

\subsection{Endpoint}

\begin{lstlisting}[style=code]
POST /conf/wifi/confirm
\end{lstlisting}

O corpo da requisição é vazio.

Ao receber essa requisição, o dispositivo deve:

\begin{enumerate}
    \item salvar/confirmar o estado da configuração;
    \item encerrar o modo AP;
    \item reiniciar;
    \item selecionar a rede Wi-Fi com melhor sinal;
    \item conectar-se à rede;
    \item iniciar a conexão \mqtt{}.
\end{enumerate}

O instalador será desconectado do AP durante esse processo.

Após essa etapa, \textbf{o \http{} deixa de participar do processo de
configuração}.


Após o reinício, o dispositivo procura as redes previamente configuradas.

Entre as redes disponíveis, ele deve selecionar aquela que apresentar o
melhor sinal.

Após estabelecer a conexão Wi-Fi, o dispositivo inicia a comunicação com o
broker \mqtt{}.

A partir desse momento:

\begin{quote}
\textbf{Toda comunicação de configuração, provisionamento e instalação será
realizada através de \mqtt{}.}
\end{quote}

Isso inclui:

\begin{itemize}
    \item timers das bombas;
    \item corrente de operação;
    \item corrente de repouso;
    \item certificados;
    \item chave privada;
    \item CA;
    \item status de configuração;
    \item status de instalação.
\end{itemize}

Não existem endpoints \http{} para essas operações.


O dispositivo conecta-se ao broker utilizando seu identificador.

Exemplo:

\begin{lstlisting}[style=code]
laundryctrl-AABBCCDDEEFF
\end{lstlisting}

O certificado de fábrica será utilizado inicialmente para permitir a conexão
necessária ao processo de provisionamento.

Um dispositivo normalmente ainda não possui registro no servidor.

Entretanto, pode ocorrer de um dispositivo previamente registrado ser
regravado com o firmware de fábrica.

Nesse caso, seu identificador já estará presente no banco de dados.

\textbf{O broker não deve rejeitar a conexão simplesmente porque o dispositivo
já está registrado.}

O processo deve permitir que o dispositivo obtenha novamente seus
certificados.


Após estabelecer a conexão com o broker, o servidor envia todas as
configurações operacionais através de \mqtt{}.

\subsection{Timers das bombas}

O dispositivo possui sete timers para acionamento das bombas.

\subsubsection{Tópico}

\begin{lstlisting}[style=code]
laundryctrl-id/config/pumps/timers
\end{lstlisting}

\subsubsection{Payload}

\begin{lstlisting}[style=json]
{
    "timers": [x, x, x, x, x, x, x]
}
\end{lstlisting}

Cada posição do vetor representa o timer de uma das sete bombas.

Os valores são definidos em milissegundos.

\subsubsection{Resultado}

O dispositivo publica o resultado em:

\begin{lstlisting}[style=code]
laundryctrl-id/config/pumps/timers/result
\end{lstlisting}

\subsubsection{Payload}

\begin{lstlisting}[style=json]
{
    "result": 1
}
\end{lstlisting}

onde:

\begin{itemize}
    \item \texttt{0}: falha ao salvar;
    \item \texttt{1}: configuração salva com sucesso.
\end{itemize}


O dispositivo possui duas configurações relacionadas à corrente:

\begin{itemize}
    \item \textbf{corrente de operação};
    \item \textbf{corrente de repouso}.
\end{itemize}

Esses valores serão configurados pelo servidor através de \mqtt{}.

\subsection{Tópico}

\begin{lstlisting}[style=code]
laundryctrl-id/config/current
\end{lstlisting}

\subsection{Payload}

\begin{lstlisting}[style=json]
{
    "operating": x,
    "idle": y
}
\end{lstlisting}

Onde:

\begin{itemize}
    \item \texttt{operating}: corrente de operação;
    \item \texttt{idle}: corrente de repouso.
\end{itemize}

A unidade utilizada deve ser definida de forma consistente entre firmware e
servidor.

\subsection{Resultado}

O dispositivo publica:

\begin{lstlisting}[style=code]
laundryctrl-id/config/current/result
\end{lstlisting}

\subsection{Payload}

\begin{lstlisting}[style=json]
{
    "result": 1
}
\end{lstlisting}

onde:

\begin{itemize}
    \item \texttt{0}: falha ao salvar;
    \item \texttt{1}: configuração salva com sucesso.
\end{itemize}


O dispositivo solicita a CA através do tópico:

\begin{lstlisting}[style=code]
laundryctrl-id/broker/req/ca
\end{lstlisting}

\subsection{Payload da requisição}

\begin{lstlisting}[style=json]
{
    "request": 1
}
\end{lstlisting}

O broker responde:

\begin{lstlisting}[style=json]
{
    "result": 1,
    "document": "[CA completo]"
}
\end{lstlisting}

O campo \texttt{document} contém o certificado CA completo.


O dispositivo solicita seu certificado através do tópico:

\begin{lstlisting}[style=code]
laundryctrl-id/broker/req/certificate
\end{lstlisting}

\subsection{Payload da requisição}

\begin{lstlisting}[style=json]
{
    "request": 1
}
\end{lstlisting}

O broker responde:

\begin{lstlisting}[style=json]
{
    "result": 1,
    "document": "[CERTIFICADO completo]"
}
\end{lstlisting}

O dispositivo solicita sua chave através do tópico:

\begin{lstlisting}[style=code]
laundryctrl-id/broker/req/key
\end{lstlisting}

\subsection{Payload da requisição}

\begin{lstlisting}[style=json]
{
    "request": 1
}
\end{lstlisting}

O broker responde:

\begin{lstlisting}[style=json]
{
    "result": 1,
    "document": "[CHAVE completa]"
}
\end{lstlisting}

A chave deve ser armazenada de forma segura no dispositivo.

Depois que CA, certificado e chave forem recebidos e armazenados
corretamente, o dispositivo publica:

\begin{lstlisting}[style=code]
laundryctrl-id/broker/register/result
\end{lstlisting}

\subsection{Sucesso}

\begin{lstlisting}[style=json]
{
    "register": 1
}
\end{lstlisting}

\subsection{Falha}

\begin{lstlisting}[style=json]
{
    "register": 0
}
\end{lstlisting}

Onde:

\begin{itemize}
    \item \texttt{0}: falha ao salvar os arquivos;
    \item \texttt{1}: arquivos salvos com sucesso.
\end{itemize}

Após concluir o provisionamento e receber as configurações necessárias, o
dispositivo inicia automaticamente o processo de instalação.

A instalação normalmente possui duração entre 2 e 5 minutos.

O progresso da instalação é informado \textbf{exclusivamente através de
MQTTS}.

Não existe endpoint HTTP para consulta do progresso.

\subsection{Tópico}

\begin{lstlisting}[style=code]
laundryctrl-id/installation/status
\end{lstlisting}

O dispositivo publica automaticamente seu estado.

\subsection{Durante a instalação}

\begin{lstlisting}[style=json]
{
    "status": "0-100%"
}
\end{lstlisting}

\subsection{Instalação concluída}

\begin{lstlisting}[style=json]
{
    "status": "completed"
}
\end{lstlisting}

\subsection{Instalação com falha}

\begin{lstlisting}[style=json]
{
    "status": "failed"
}
\end{lstlisting}

Caso o processo de instalação falhe, o dispositivo reinicia automaticamente
e tenta realizar novamente o processo.

Não é necessário repetir a configuração inicial do Wi-Fi, desde que as redes
tenham sido salvas corretamente.

As configurações armazenadas anteriormente também podem ser utilizadas
novamente pelo dispositivo.

Quando o processo de instalação for concluído com sucesso, o dispositivo
inicia normalmente com o firmware de produção.

A partir desse momento, o equipamento entra em seu estado operacional normal.

A comunicação entre o dispositivo e o broker utiliza MQTTS com TLS.

O firmware de fábrica possui credenciais suficientes para estabelecer a
comunicação inicial necessária ao processo de provisionamento.

Durante o processo de registro, o dispositivo obtém:

\begin{itemize}
    \item CA;
    \item certificado;
    \item chave privada.
\end{itemize}

Esses arquivos passam a ser utilizados para as conexões MQTTS subsequentes.

Os dados armazenados na memória do dispositivo são protegidos pelos
mecanismos de criptografia de memória disponíveis no hardware.

\begin{quote}
\textbf{
HTTP é utilizado somente enquanto o dispositivo está no processo de
configuração inicial do Wi-Fi. Depois que o dispositivo reinicia e estabelece
sua conexão Wi-Fi, todo o restante do processo ocorre exclusivamente através
de MQTTS.
}
\end{quote}
